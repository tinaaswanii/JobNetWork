☕JDK vs JRE vs JVM?

The JVM runs bytecode and is platform-specific. The JRE is the JVM plus the core libraries needed to run programs. The JDK is the JRE plus development tools like the compiler (javac) and debugger. JDK contains JRE, which contains JVM.

⚠️ "Write once, run anywhere" works because javac produces platform-independent bytecode — but each OS needs its own JVM to run it.

🌍Why is Java platform independent?

Source code compiles to bytecode, not machine code, and any machine with a JVM can run that bytecode. It's the JVM that's platform-specific, not your compiled code.

🏛️The four pillars of OOP, with an example

Encapsulation keeps a field private with validated getters/setters. Inheritance lets a subclass extend a shared base. Polymorphism means calling a method on a parent reference runs whichever subclass's version actually got created. Abstraction means an abstract class declares what must be done without exposing how.

abstract class Payment {
  abstract void process();
}
class UpiPayment extends Payment {
  void process() { /* ... */ }
}
Payment p = new UpiPayment();
p.process(); // resolved at runtime — polymorphism

🔁Overloading vs overriding?

Overloading: same class, same name, different parameters, resolved at compile time. Overriding: parent/child, same signature, resolved at runtime. You cannot override a static, final, or private method.

class Calc {
  int add(int a, int b) { return a + b; }
  double add(double a, double b) { return a + b; } // overload
}
class Dog extends Animal {
  void sound() { System.out.println("Woof"); } // override
}

🧩Abstract class vs interface?

A class extends only one abstract class but implements many interfaces. Abstract classes hold fields and a mix of abstract/concrete methods and can have constructors; interfaces (Java 8+) can add default/static methods but no constructors.

⚠️ Reach for an abstract class for shared base code ("is-a"), an interface for a capability contract ("can-do").

🔒Why is String immutable?

Four reasons: security (strings hold things like paths/usernames), the string pool (can only share literals safely if nothing mutates), thread safety (immutable objects need no synchronization), and hash caching (hashCode() computed once and reused).

✍️String vs StringBuilder vs StringBuffer?

String: immutable, thread-safe, slow for repeated edits. StringBuilder: mutable, fastest, not thread-safe. StringBuffer: mutable, thread-safe (synchronized), slower than StringBuilder.

⚠️ Default to StringBuilder for building strings in a loop; only use StringBuffer if multiple threads genuinely share it.

🚨Checked vs unchecked exceptions?

Checked: verified at compile time, must handle or declare (IOException, SQLException). Unchecked: extend RuntimeException, not compiler-enforced (NullPointerException, ArrayIndexOutOfBoundsException). Errors like OutOfMemoryError are serious JVM problems you don't try to catch.

📋ArrayList vs LinkedList?

ArrayList: dynamic array — O(1) get, O(1) amortized add at end, O(n) insert/remove in the middle. LinkedList: doubly linked list — O(n) get, O(1) add/remove at ends.

⚠️ Default to ArrayList — it usually wins even for middle inserts because of cache-friendly memory layout.

🗺️How does HashMap work internally?

key.hashCode() picks a bucket. A collision compares keys with equals() — match replaces the value, else the entry joins the bucket's chain (tree-ified past 8 entries, since Java 8). Resizes when size exceeds capacity × load factor (default 0.75).

⚠️ You must override hashCode() whenever you override equals(), or equal objects can land in different buckets.

🧵Two ways to create a thread — which is better?

Extend Thread and override run(), or implement Runnable and pass it to a Thread. Runnable is generally preferred — Java has single inheritance, and Runnable separates the task from the threading mechanism.

⚠️ Common trap: calling start() creates a new thread; calling run() directly just runs it like a normal method on the current thread.

λLambdas and functional interfaces?

A functional interface has exactly one abstract method (Runnable, Comparator). A lambda implements one inline. Common built-ins: Predicate<T>, Function<T,R>, Consumer<T>, Supplier<T>.

Runnable r = () -> System.out.println("hello");
Comparator<Integer> c = (a, b) -> b - a;

🌊What is the Stream API?

Streams process collections declaratively in three stages: a source, lazy intermediate operations, and one terminal operation that triggers execution — a pipeline instead of explicit loops.

List<String> result = names.stream()
    .filter(n -> n.startsWith("A"))
    .map(String::toUpperCase)
    .sorted()
    .collect(Collectors.toList());

🧱Stack vs heap memory?

The stack holds method frames, local variables and references — per-thread, fast, auto-cleaned on return. The heap holds the actual objects — shared, managed by the garbage collector.

⚠️ StackOverflowError = stack full (deep/infinite recursion). OutOfMemoryError = heap full.
